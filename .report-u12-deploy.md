## Review fixes

- Moved rollback-state recording until after both requested commits are proven
  reachable from freshly fetched `origin` refs, while still recording before
  either checkout changes.
- Preserved the known-good rollback target when a rollback attempt itself fails;
  the previous pair rotates only after a successful rollback.
- Made Compose service discovery and an empty service set fail closed.
- Kept an active approved deploy running while GitHub collapses newer queued
  runs (`cancel-in-progress: false`).

## Judgments that differ from the task wording

- `deploy/compose.dev.yaml` contains services without Docker healthchecks. The
  post-deploy assertion therefore requires every Compose service to be running
  and every service that declares a healthcheck to report `healthy`. Requiring a
  literal Docker `healthy` state from services with no healthcheck would make
  every deploy fail and would contradict the current Compose authority and
  `docker compose up --wait` semantics.
- The source script is executable in Git, but the security-relevant ownership
  and `0755` mode remain properties of the orchestrator's installation at
  `/usr/local/sbin/ontokit-deploy`, as specified.

No other implementation decision differs from the task specification or the
runbook/Compose authority.
