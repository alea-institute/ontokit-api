# PR 15 review-finding resolution

## Per-finding disposition

1. **PostgreSQL credentials — fixed.** `POSTGRES_PASSWORD` and
   `ONTOKIT_DB_PASSWORD` are required Compose interpolations. The API and worker
   URLs share the application-role password, and Zitadel's administrative
   connection shares the PostgreSQL superuser password. Both keys are documented
   in `deploy/.env.example`.
2. **MinIO credentials — fixed.** The MinIO root user and password are required
   interpolations shared consistently by MinIO, API, and worker. Both keys are
   documented in `deploy/.env.example`.
3. **Zitadel role bootstrap — fixed.** Fresh DEV volumes mount the deploy-owned
   `deploy/init-db.dev.sh`. Compose forwards `ZITADEL_DB_PASSWORD` and
   `ONTOKIT_DB_PASSWORD` into PostgreSQL, and the entrypoint script uses those
   values for role creation. The repository-local `scripts/init-db.sh` was not
   changed.
4. **Cold bootstrap order — fixed.** The runbook now generates secrets first,
   installs the firewall, starts the stack without web, invokes
   `setup-zitadel.sh` with the exact deployed URL/volume/env-file variables,
   explicitly supplies all auth-sensitive web build args, and recreates
   API/worker/web after credentials are written. All existing gotchas remain.
5. **Image pins — fixed.** Mailpit, Login V2, Zitadel, pgvector, Redis, and MinIO
   use the supplied immutable DEV digests, with their former readable tags in
   trailing comments.
6. **IPv6 — refuted with evidence; documented, no rule change.** The firewall
   script records that the proxy is IPv4-only and this host's published IPv6
   traffic terminates at userland `docker-proxy` sockets filtered by INPUT;
   external F9-v6 probes were refused. It also records that enabling Docker
   native IPv6 forwarding with `"ip6tables": true` would require a
   DOCKER-USER-equivalent IPv6 forwarding rule set.
7. **Stacked branch surgery — resolved by the orchestrator.** The updated base
   was merged as directed, clearing the scratch-report deletion noise without
   changing this finding-fix scope.
